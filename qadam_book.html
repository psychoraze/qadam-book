Switched on

Astana, a cold October morning. In a university lab, Aru presses the power button.

Aru: Hello, Qadam. Can you hear me?

Qadam: Sensors on. Hello! What am I?

Aru: You're an agent. You sense the world and you act in it.

Qadam: Then I need a goal. Without one, every action is as good as any other.

Aru: Reach Almaty and pass the robot review. Then you can work in public.

Qadam: Qadam means "step". Let's take the first one.

Before Qadam can plan, learn or play games, we need to say what an artificial intelligence actually is. The answer that runs through this whole book is simple: an AI is an agent that perceives its world and chooses actions to reach its goals as well as it can.

Agents

An agent is anything that perceives its environment through sensors and acts on it through actuators. Qadam's sensors are a camera, a colour sensor and a battery gauge; its actuators are its wheels and arms. A chess program is an agent too: its "sensor" reads the board and its "actuator" is the move it outputs.

What the agent senses at one moment is a percept. The agent's job is to map everything it has perceived so far to the next action. The rest of this book is about different ways to do that mapping well.

Rational, not all-knowing

A rational agent chooses the action with the best expected result, given the evidence it has right now. This is different from an omniscient agent, which knows the actual future and does not exist outside thought experiments.

The difference matters. If Qadam takes the safest road and a sudden storm still delays it, the decision was not irrational. Rationality is judged by what the agent knew before acting, not by hindsight.

Four ways to define AI

Russell and Norvig's textbook sorts definitions of AI into four groups:

  1. Thinking like humans: model how people's minds work.
  2. Acting like humans: behave so that people can't tell the difference. This is Alan Turing's test from 1950.
  3. Thinking rationally: use correct logical reasoning.
  4. Acting rationally: do the right thing given what you know. This is the view this course and this book take.

  1. 1950Alan Turing asks "Can machines think?" and proposes the imitation game, now called the Turing test.
  2. 1956The Dartmouth workshop gives the field its name: artificial intelligence.
  3. 1958Frank Rosenblatt builds the perceptron, the first neuron that learns from examples (Chapter 8).
  4. 1969Minsky and Papert show that one perceptron cannot learn XOR. Funding falls: the first "AI winter".
  5. 1986Backpropagation is popularized for training networks with hidden layers.
  6. 1997IBM's Deep Blue beats world chess champion Garry Kasparov (Chapter 3).
  7. 2012AlexNet wins the ImageNet contest and starts the deep learning boom.

Myth

AI means a machine that thinks like a person.

Fact

Most AI today is narrow: it does one task well, like routing or spam filtering. A system with human-level ability across many tasks (general AI) does not exist yet.

Did you know?

The 1956 Dartmouth proposal expected that "a significant advance" could be made in a single summer by a small group of researchers. Some of its problems, like understanding language, took more than sixty years.

Finding the way

Qadam: Astana to Almaty. There are so many roads. Which one?

Aru: Don't drive yet. Search first: try plans in your head.

Qadam: I could check every road one step at a time… or always extend the cheapest plan so far.

Aru: And if you can estimate how far is left, you'll waste even less time.

Qadam: Found it: the main road through Karaganda and Balkhash. And I can prove it's the cheapest.

A planning agent asks "what if I take this action?" before it moves. It explores possible plans in its head until one reaches the goal. All the algorithms in this chapter do that; the only difference between them is which waiting plan they explore next.

What is a search problem?

A search problem has four parts. Here they are for Qadam's trip, using the lecture's own example:

PartMeaningQadam's trip
State spaceAll the situations that matterThe cities
Successor functionActions available, with their costsRoads to neighbouring cities, cost = distance
Start stateWhere we beginAstana
Goal testHave we arrived?Is the city Almaty?

A solution is a sequence of actions from the start to a goal. Notice that the state is an abstraction: it keeps only what planning needs (which city), not the weather or the colour of Qadam's paint.

Two pictures of the same problem are useful. In the state-space graph every state appears once and arrows are actions. In the search tree the root is the start and every node stands for a whole plan (a path), so the same city can appear many times. The plans waiting to be explored are called the frontier (or fringe), and taking one off the frontier to look at its successors is called expanding it.

Four strategies

AlgorithmExpands nextFrontier is a…Finds the best path?
BFS breadth-firstThe shallowest plan (fewest steps)FIFO queue: first in, first outOnly if every step costs the same
DFS depth-firstThe deepest planLIFO stack: last in, first outNo; it returns the first goal it stumbles on
UCS uniform-costThe plan with the lowest cost so far, g(n)Priority queueYes, when costs are positive
A*The lowest f(n) = g(n) + h(n)Priority queueYes, with an admissible (tree) or consistent (graph) heuristic

BFS is complete and, for equal step costs, finds the fewest steps, but it must hold a whole layer of the tree in memory. DFS uses very little memory but can wander down a long branch. Iterative deepening runs DFS with depth limit 1, then 2, then 3, and so on: it keeps DFS's small memory and BFS's preference for short solutions. The repeated work is small because most nodes sit at the deepest level.

# BFS and DFS differ in one line: popleft() vs pop()
from collections import deque

def bfs(graph, start, goal):
    queue = deque([(start, [start])])      # FIFO frontier
    while queue:
        state, path = queue.popleft()
        if state == goal:
            return path
        for nxt in graph[state]:
            queue.append((nxt, path + [nxt]))
    return None

def dfs(graph, start, goal):
    stack, visited = [(start, [start])], set()   # LIFO frontier
    while stack:
        state, path = stack.pop()
        if state == goal:
            return path
        if state not in visited:
            visited.add(state)
            for nxt in graph[state]:
                if nxt not in visited:
                    stack.append((nxt, path + [nxt]))
    return None

On the lecture's example graph (A→B, C; B→D, E; C→F; E→G) BFS returns A → B → E → G. One slide shows "A → C → F", which cannot be right because F is not the goal; another calls bfs at the end of the DFS code. Both are corrected here.

Why the number of steps is not enough

Worked example: BFS vs UCS

A → B costs 2, B → F costs 10, A → C costs 8, C → F costs 1.

  1. Both routes to F take two steps, so BFS sees them as equally good.
  2. UCS adds the costs: A-B-F = 2 + 10 = 12, A-C-F = 8 + 1 = 9.
  3. UCS returns A-C-F. Cheaper beats shorter.

A*: adding a good guess

f(n) = g(n) + h(n)g(n): exact cost paid so far · h(n): estimated cost still to go · f(n): estimated total cost of the best plan through n

The estimate h(n) is a heuristic: a rule of thumb that points the search in a promising direction. UCS asks "what have I paid so far?". A* also asks "how far do I probably still have to go?".

  • Admissible heuristic: never overestimates, 0 ≤ h(n) ≤ h*(n), where h*(n) is the true remaining cost. Straight-line distance on a map is admissible because no road is shorter than a straight line.
  • Consistent heuristic: h(n) ≤ cost(n, n′) + h(n′) for every step from n to its successor n′ ("n prime"). A* with a visited set (graph search) needs this. Every consistent heuristic is also admissible.
  • If h = 0, A* becomes UCS. If h overestimates, A* may be faster but can return a worse path. Using only h is greedy best-first search, which is not optimal.

Worked example: which node does A* expand?

Nodeg(n)h(n)f(n)
A21012
B549
C7310

A* expands B. It has already cost more than A, but its estimated total is the lowest.

Why A* is optimal. Let A be the best goal and B a worse goal sitting on the frontier. Some ancestor n of A is also on the frontier. Because h never overestimates, f(n) ≤ f(A), and because B is worse, f(A) < f(B). So n is expanded before B, and the same holds for every ancestor of A. A is reached before B.

Try it

Four searches, one map

Qadam starts at S and must reach G. Road costs 1, mud costs 5. Run each algorithm and compare how many cells it explores and what its path costs. BFS takes the 13-step route straight through the mud (cost 25); UCS and A* go around (21 steps, cost 21). A* finds the same cheapest path as UCS while exploring fewer cells, because its heuristic points it toward G. DFS wanders and returns a long, expensive path.

Myth

The route with the fewest roads is the cheapest route.

Fact

Only when every road costs the same. With different costs, BFS can return an expensive path; UCS and A* compare total cost.

Did you know?

A* was published in 1968 by Peter Hart, Nils Nilsson and Bertram Raphael at the Stanford Research Institute, for Shakey, one of the first mobile robots. Its ideas still sit under route planners and video-game pathfinding.

Making it better

Before leaving Astana, Qadam helps a courier with eight stops: Baiterek, EXPO, Khan Shatyr, the station, the airport…

Qadam: Here it's not about how I find the order. Only the final route matters.

Qadam: Start with any route. Swap two stops. 76 km became 68 km: keep it. Swap again…

Qadam: No single swap helps any more. Is this the best route, or just a small hill?

Aru: Try a few bad moves on purpose. Then cool down.

Chapter 1 searched for a path. Many real problems only care about the final configuration: a delivery order, a timetable, where to place 8 queens on a chessboard. Local search keeps one (or a few) complete candidate solutions and keeps improving them with small changes. It forgets the path, so it needs very little memory.

The vocabulary

TermMeaningCourier example

NeighbourA small change to the stateSwap two stops, or reverse a section (2-opt)
Objective functionOne number for how good a state is, to maximize or minimizeTotal distance in km (minimize)

The lecture's courier question: the route was 76 km, and after swapping two addresses it is 68 km. Since we are minimizing distance, the algorithm accepts the change.

Hill climbing

Hill climbing is the simplest local search: look at the neighbours, move to the best one if it is better, and stop when none is.

Worked example: climbing a list

Values [1, 3, 5, 8, 6, 4, 2], starting at index 0. Neighbours are the positions to the left and right.

  1. At value 1: the neighbour 3 is better, move.
  2. At 3: neighbour 5 is better, move. At 5: neighbour 8 is better, move.
  3. At 8 (index 3): the neighbours are 5 and 6. Neither is better, so stop and return 8.

Hill climbing is fast but greedy, and it fails in three typical ways:

  • Local maximum: a peak higher than its neighbours but lower than the best peak (the global maximum).
  • Plateau: a flat area where all neighbours have the same value, so there is no direction to climb.
  • Ridge: the way up needs a sequence of moves, but no single neighbour is better.

The simplest fix is random-restart hill climbing: run hill climbing from several random starts and keep the best result. More computation, less dependence on one unlucky start.

Simulated annealing

Simulated annealing picks a random neighbour. A better move is always accepted. A worse move is accepted sometimes, with a probability controlled by a number called the temperature T. The name comes from metalwork: metal heated and cooled slowly settles into a strong structure.

P(accept a worse move) = e^(ΔE / T)ΔE = new value − current value. A worse move (when maximizing) has ΔE < 0.
A move that is 2 points worse (ΔE = −2)Chance of acceptingBehaviour
T = 10 (hot)e^(−0.2) ≈ 82%Explores, crosses valleys
T = 1e^(−2) ≈ 14%Mostly climbs
T = 0.1 (cold)e^(−20) ≈ 0%Same as hill climbing

The temperature starts high and falls according to a cooling schedule; the lecture's code multiplies it by 0.95 each step. Cool too fast and the search freezes on a poor solution; cool too slowly and it wastes computation. The lecture's flood-rescue example shows why this matters: hill climbing gets stuck on a route that looks short but is dangerous, while annealing accepts a temporarily worse step and later finds a route that is both safe and efficient.

Two classic configuration problems: in N-queens, a state places one queen per column, a neighbour moves one queen within its column, and the objective counts attacking pairs (goal: 0). Myth

If no small change improves the solution, it must be the best possible solution.

Fact

It is only a local optimum. A better solution can sit on another hill, reachable only by first getting worse.

Did you know?

Simulated annealing was introduced for optimization in 1983 by Kirkpatrick, Gelatt and Vecchi, who borrowed the idea from the physics of cooling metals and used it to design computer chips.

Playing against a rival

Ata: Young robot! One game of togyz kumalak before you go?

Qadam: Nine holes each and 162 stones. I accept.

Qadam: If I play here, Ata answers with his best move. Then I answer his… The board isn't just mine any more.

Qadam: I'll assume he always plays perfectly. Then nothing he does can surprise me.

Ata: Ha! Careful. Old men have tricks.

Until now Qadam controlled every move. In a game, another agent chooses half the moves and wants Qadam to lose. The question changes from "which actions reach the goal?" to "which move is best after my opponent's best reply?" The opponent is part of the model, not noise added later.

Describing a game

A game has states, players, actions, a transition model, a terminal test (is the game over?) and a utility (the final score, such as +1 win, 0 draw, −1 loss). Games come in types: deterministic or with chance (dice), two-player or many, perfect information (both see the board) or imperfect (hidden cards). Togyz kumalak, like chess, is deterministic, two-player and perfect-information.

Most classic games are zero-sum: one player's gain is exactly the other's loss. Then a single number describes every outcome. One player, MAX, wants it high; the other, MIN, wants it low. (In general-sum games, players have separate utilities and can cooperate.)

Minimax

A game tree alternates levels: MAX moves, then MIN, then MAX… The leaves hold utilities. Minimax computes each node's value from the bottom up:

terminal: V(s) = U(s) · MAX node: V(s) = max V(s′) · MIN node: V(s) = min V(s′)s′ ("s prime") ranges over the children of s, the positions reachable in one move

Worked example (from the lecture)

  1. The left MIN node has leaves 3, 12, 8. MIN picks the smallest: 3.
  2. The middle MIN node has 2, 4, 6: value 2. The right one has 14, 5, 2: value 2.
  3. MAX picks the largest MIN value: max(3, 2, 2) = 3, so it moves left.
  4. Why not chase the 14 on the right? Because MIN chooses inside that branch and would pick 2. Minimax measures what MAX can guarantee, not the biggest number in sight.

Minimax is optimal against an optimal opponent, and conservative: it always prepares for the worst. Its cost is the problem. With branching factor b and depth m, it looks at about b^m positions, which grows exponentially.

Alpha–beta pruning

Alpha–beta pruning skips branches that cannot change the decision. It tracks two numbers along the current path:

  • α (alpha): the best value MAX can already guarantee.
  • β (beta): the best (lowest) value MIN can already guarantee.
  • Start with α = −∞ and β = +∞. MAX updates α, MIN updates β. When α ≥ β, stop exploring that node's remaining children.

On the lecture tree: after the left MIN node returns 3, the root knows α = 3. In the middle MIN node the first leaf is 2. MIN can now force 2 or less there, and MAX already has 3, so leaves 4 and 6 never need to be looked at. The right MIN node has to see 14, 5 and then 2 before its value drops below 3. Result: 7 of 9 leaves examined, same answer of 3.

Pruning never changes the root value. It only saves work, and it saves more when good moves are tried first (move ordering). With perfect ordering, alpha–beta can search about twice as deep in the same time.

Real games are too big

Chess and togyz kumalak cannot be searched to the end. Instead, search to a fixed depth and score the positions there with an evaluation function, a weighted sum of features:

Eval(s) = w₁f₁(s) + w₂f₂(s) + … + wₙfₙ(s)chess features: material, mobility, king safety, centre control; togyz kumalak: stones in your kazan (store), stones still in play

A depth limit causes the horizon effect: a disaster one move past the limit is invisible, so a position looks good just before it turns bad. An evaluation function is like A*'s heuristic in that both add domain knowledge, but a heuristic estimates remaining path cost while an evaluation function estimates how good a game position is.

Expectimax: when the opponent is luck

When outcomes are random (dice, a ghost that moves at random), assuming the worst is too pessimistic. Expectimax replaces MIN nodes with chance nodes that take the probability-weighted average:

V(chance) = Σ P(s′) · V(s′)

Worked example

Outcomes 8, 24, −12 with probabilities 1/2, 1/3, 1/6: (1/2)·8 + (1/3)·24 + (1/6)·(−12) = 4 + 8 − 2 = 10.

Choose the model that matches reality. Treating a clever opponent as random is dangerously optimistic; treating random events as a clever enemy is needlessly pessimistic.

Myth

Alpha–beta is a faster but less accurate version of minimax.

Fact

It returns exactly the same value and move. It only skips branches that provably cannot matter.

Did you know?

Togyz kumalak ("nine pebbles") is a traditional Kazakh board game. Each player has nine holes with nine stones in each, 162 stones in total. Captured stones go to the player's kazan; the first to collect more than 81 wins. For computers it is the same kind of game as chess: two players, no luck, nothing hidden.

Learning by trying

Qadam: Battery at 20%. The sun is strong now, but Balkhash is far.

Qadam: Charge now, or drive now? Every choice changes what I can do later. And my wheels sometimes slip.

Qadam: Nobody gave me a rulebook for the steppe. I'll learn from what each choice brings me.

Today's action changes tomorrow's situation, and actions don't always do what you intend: Qadam presses RIGHT and sometimes slips DOWN. A fixed path is no longer enough. Qadam needs a policy: a decision for every situation it might end up in.

The Markov decision process

A Markov decision process (MDP) describes this kind of problem with five parts:

PartMeaningQadam's battery
States SThe situations that matterBattery level, sunlight, hour, distance left
Actions AThe choicesCharge, hold, drive
Transitions P(s′ | s, a)Probability of landing in s′ after doing a in sDriving uphill may drain more than expected
Rewards RImmediate feedback+10 for arriving, −1 per hour, −200 for an empty battery
Discount γHow much the future counts (0 to 1)0.9

The word Markov means the next state depends only on the current state and action, not on the whole history. That is why the state must contain everything relevant: if the state were only the battery level, Qadam could not tell a sunny noon from midnight, and no algorithm could learn to charge at the right time.

Reward, return and value

A reward is immediate. The return G adds up all future rewards, each one discounted by γ for every step it lies in the future:

G = R₁ + γR₂ + γ²R₃ + …Rewards 5, 10, 20 with γ = 0.9: G = 5 + 0.9·10 + 0.81·20 = 5 + 9 + 16.2 = 30.2
A reward of 100 that arrives 10 steps from now is worth γ¹⁰ × 100 todayγ = 0.5γ = 0.8γ = 0.9γ = 0.99
Value today0.1010.7434.8790.44

A γ near 0 makes the agent short-sighted; near 1 it plans far ahead. With γ below 1, even an endless stream of rewards adds up to a finite number.

The value V(s) of a state is the expected return from that state if the agent follows its policy. The Q-value Q(s, a) is the expected return from taking action a in state s and then following the policy. Reward is not value: a spot right before the finish may give 0 reward now but be very valuable, because +100 comes next. If Q(A, LEFT) = 2, Q(A, RIGHT) = 8, Q(A, UP) = 4 and Q(A, DOWN) = −5, then V*(A) = 8 and the best action is RIGHT.

The Bellman equation

The value of a state equals the immediate reward plus the discounted value of where you land. For the best possible policy:

V*(s) = max over a of Σ P(s′ | s, a) · [ R + γ · V*(s′) ]

Worked example: value flows backward

  1. Each step costs −1, γ = 0.9, and the goal is worth 10.
  2. The state just before the goal: V = −1 + 0.9 × 10 = 8.
  3. The state before that: V = −1 + 0.9 × 8 = 6.2. One more step back: −1 + 0.9 × 6.2 = 4.58.
  4. With slipping: RIGHT reaches GOOD (V = 10) 80% of the time and BAD (V = −5) 20% of the time. Q = 0.8 × (−1 + 9) + 0.2 × (−1 − 4.5) = 6.4 − 1.1 = 5.3.

Two ways to solve an MDP

If the transitions and rewards are known, we can plan. Value iteration applies the Bellman update to every state again and again until the values stop changing. Policy iteration evaluates the current policy, improves it by picking the best action in each state, and repeats.

If they are unknown, Qadam must learn from experience. That is reinforcement learning (RL). There are no correct answers to copy, only rewards; feedback can be delayed; and Qadam's own actions decide what data it sees. Its experience arrives as transitions (s, a, r, s′).

  • Monte Carlo: wait until the episode ends, then move the estimate toward the real return: V ← V + α(G − V).
  • Temporal-difference (TD) learning: update after a single step, using the next state's estimate. The TD error δ = r + γV(s′) − V(s) measures surprise. Example: V(A) = 5, reward 2, V(B) = 8, γ = 0.9 → target 9.2, δ = 4.2, so A was better than expected.

Q-learning

Q(s, a) ← Q(s, a) + α · [ r + γ · max Q(s′, a′) − Q(s, a) ]current belief + learning rate × (new evidence − current belief)

Worked example: one update

  1. Q(A, RIGHT) = 4, reward r = 2, best Q in the next state B = 8, γ = 0.9, α = 0.5.
  2. Target = 2 + 0.9 × 8 = 9.2.
  3. Error = 9.2 − 4 = 5.2.
  4. New Q = 4 + 0.5 × 5.2 = 6.6. Experience was better than expected, so the action became more valuable.

Three parameters, three different jobs:

  • α, the learning rate: how much one experience changes the estimate.
  • γ, the discount: how much the future counts.
  • ε, the exploration rate: how often to try a random action. With ε-greedy and ε = 0.1, Qadam explores about 10% of the time and uses its best-known action 90% of the time. Too little exploration locks in a mediocre habit; too much wastes reward.

SARSA is Q-learning's close relative. Q-learning's target uses the best next action (off-policy); SARSA's uses the action Qadam actually takes next, exploration included (on-policy). That makes SARSA more careful near dangerous states while it is still exploring.

When the table gets too big

The lecture's battery example: 10 battery levels × 20 prices × 20 demand levels × 20 solar levels × 24 hours = 1,920,000 states, and with 3 actions, 5,760,000 Q-values. A table cannot hold every situation from a camera image either. Deep reinforcement learning replaces the table with a neural network (Chapter 8):

  • DQN (Deep Q-Network): a network estimates Q(s, a) and generalizes between similar states. A replay buffer and a target network keep training stable.
  • Policy gradient: learn the policy directly; natural for continuous actions like steering angle.
  • Actor–critic: the actor chooses actions ("what should I do?"), the critic estimates value ("how good was that?") and guides the actor.

Real deployments add safety: a badly written reward gets optimized literally, so hard limits belong outside the reward, and training starts in simulators before real equipment.

Fact

Thinking in probabilities

Morning at a guesthouse by the lake. The grass is wet.

Qadam: Did it rain last night? Or was it the sprinkler?

Qadam: Wet grass is evidence, not proof. Rain was 20% likely before. Now… 35.8%.

Host: I ran the sprinkler at dawn.

Qadam: Then rain drops to 0.7%. The sprinkler explains it away!

Real observations are noisy. A fever does not prove a disease and a hot motor does not prove a failure. Probability lets Qadam hold a degree of belief in each explanation and update it when evidence arrives.

The basics

A random variable is a quantity whose value is uncertain, like Rain ∈ {true, false} or Weather ∈ {sunny, cloudy, rainy}. A distribution gives every possible value a probability, and the probabilities sum to 1 (sunny 0.5 + cloudy 0.3 + rainy 0.2 = 1).

  • Joint probability P(A, B): both happen.
  • Conditional probability P(A | B): A happens, given that we know B. It equals P(A, B) / P(B). Conditioning shrinks the group you count in.

Worked example: 100 days in Astana traffic

  1. 45 of 100 days have heavy traffic, so P(heavy) = 45%.
  2. 30 days are rainy, and on 24 of them traffic is heavy.
  3. P(heavy | rain) = 24 / 30 = 80%. The denominator changed from all 100 days to the 30 rainy ones.

Bayes' theorem

P(H | D) = P(D | H) · P(H) / P(D)P(D) = P(D | H)·P(H) + P(D | not H)·P(not H)

Read it as a recipe. Start with the prior P(H), your belief before the evidence. Multiply by the likelihood P(D | H), how expected the evidence is if H is true. Divide by P(D) so everything sums to 1 again. The result is the posterior P(H | D), your belief after the evidence.

Worked example: a medical test

1% of people have a disease. The test catches 95% of sick people (sensitivity) but also flags 10% of healthy people (false positives). Someone tests positive. How likely are they to be sick?

  1. Imagine 10,000 people: 100 are sick, and 95 of them test positive.
  2. 9,900 are healthy, and 10% of them, 990, also test positive.
  3. Positive tests: 95 + 990 = 1,085. Sick among them: 95.
  4. P(sick | positive) = 95 / 1,085 ≈ 8.76%.

A positive test raises the risk from 1% to about 9%, not to 95%, because healthy people vastly outnumber sick ones. Forgetting this is the base-rate fallacy. P(+ | sick) and P(sick | +) are different numbers. The same reasoning applies to machines: with a 2% prior failure rate and a temperature alarm that fires for 90% of failing machines and 10% of healthy ones, an alarm raises the failure risk to 0.018 / (0.018 + 0.098) ≈ 15.52%: a reason to inspect, not proof.

Bayesian networks

With many variables, a table of every combination explodes: 20 true/false variables need 2²⁰ ≈ 1,000,000 rows. A Bayesian network avoids this. It is a directed acyclic graph (arrows, no loops) where:

  • each node is a random variable;
  • each arrow is a direct dependency;
  • each node has a CPT (conditional probability table): its probability for every combination of its parents' values.
P(X₁, …, Xₙ) = Π P(Xᵢ | Parents(Xᵢ))Wet-grass network: P(Rain, Sprinkler, Wet) = P(Rain) · P(Sprinkler | Rain) · P(Wet | Rain, Sprinkler)

This works because of conditional independence: once you know a node's parents, more distant variables tell you nothing extra about it. With 20 variables and at most two parents each, you need at most 20 × 4 = 80 numbers instead of a million.

Inference: from evidence to belief

Inference means computing the probability of something hidden from what we observed. The exact method, enumeration, sums over every hidden variable and then normalizes.

Worked example: P(Rain | Wet grass)

  1. Rain and wet: 0.2 × (0.01 × 0.99 + 0.99 × 0.80) = 0.2 × 0.8019 = 0.16038.
  2. No rain and wet: 0.8 × (0.40 × 0.90 + 0.60 × 0) = 0.288.
  3. Normalize: 0.16038 / (0.16038 + 0.288) = 35.77%, up from 20%.
  4. Now also observe the sprinkler was on: 0.00198 / (0.00198 + 0.288) ≈ 0.68%. This is explaining away: two causes compete for one effect, so confirming one makes the other unlikely.

A test that is 95% accurate means a positive result is 95% certain.

Fact

It depends on the base rate. For a rare disease, most positive results can be false positives, as the 8.76% example shows.

Where am I?

Almaty at last. To earn its review fee, Qadam takes a job in a warehouse with three zones: A, B and C.

Qadam: My camera is broken. I only have a colour sensor that says RED or BLUE, and it is sometimes wrong. And I keep moving.

Chapter 5 used one observation at one moment. Now the thing Qadam wants to know (its zone) is hidden and changes over time, and every clue is noisy. A hidden Markov model (HMM) tracks it step by step: predict where Qadam moved, then correct with what the sensor says.

The filtering loop

  1. Predict: pₜ(j) = Σᵢ bₜ₋₁(i) · Tᵢⱼ. Shift the old belief through the movement probabilities.
  2. Weight: wₜ(j) = pₜ(j) · P(reading | j). Multiply in the sensor evidence.
  3. Normalize: bₜ(j) = wₜ(j) / Σ w. Divide by the total so the beliefs sum to 1.
  4. Repeat: today's belief is tomorrow's prior. Never restart from b₀.

Worked example: the first reading is RED

How HMMs connect to the rest of the book

  • Bayes (Chapter 5): every update is Bayes' theorem, with the prediction as the prior and the sensor model as the likelihood. An HMM is Bayes repeated over time; formally it is a Bayesian network unrolled through time.
  • MDPs (Chapter 4): an MDP chooses actions in a state it can see; an HMM only tracks a state it can't see. A real robot often needs both: work out where it is, then decide what to do.
  • Other questions an HMM can answer: predicting future states, smoothing (re-estimating a past state using later readings) and finding the most likely whole path (the Viterbi algorithm). HMMs are used in speech recognition, GPS tracking and robot localization.

Myth

If the sensor says RED and RED is most common in zone A, Qadam is in zone A.

Fact

One reading is weak evidence. After RED → BLUE → BLUE → RED, zone B is most likely, because the belief combines every reading with how the robot moves.

Did you know?

The same predict-then-correct idea, in a version for continuous values called the Kalman filter, helped guide the Apollo spacecraft to the Moon in the 1960s.

Deciding wisely

Qadam: The conveyor motor is hot and vibrating. My model says a 15% chance it fails this week.

Manager: 15% is low. Keep it running.

Qadam: A failure costs $20,000. Maintenance costs $2,000. Expected cost of waiting: 0.15 × 20,000 = $3,000.

Qadam: $3,000 is more than $2,000. Maintain now. A low probability can still be too expensive to ignore.

This chapter joins two jobs that are easy to mix up. Machine learning predicts what will probably happen. Decision theory decides what to do about it by weighing probabilities against costs. A model that predicts well is not automatically a system that decides well.

Expected utility

A utility is a number for how much we like an outcome. The expected utility of an action multiplies each outcome's utility by its probability and adds them up. The maximum expected utility (MEU) principle says: choose the action with the highest expected utility.

EU(a) = Σ P(oᵢ | a) · U(oᵢ) · a* = argmax EU(a)argmax means "the action that gives the largest value", not the value itself

Worked example: two projects

  1. Project A: 90% chance of +100, 10% chance of −20. EU = 0.9 × 100 + 0.1 × (−20) = 88.
  2. Project B: 60% chance of +200, 40% chance of −50. EU = 0.6 × 200 + 0.4 × (−50) = 100.
  3. B fails more often but has the higher expected utility, so it is the rational choice on this utility scale.
  4. Same idea for Qadam's routes: A = 0.8 × 100 + 0.2 × (−50) = 70; B = 0.95 × 80 + 0.05 × (−20) = 75.

A risk-neutral decision-maker cares only about the average. A risk-averse one has a curved (concave) utility for money and may prefer a safer option with a slightly lower average. Either way, a rational choice can still end badly. It is judged by what was known before acting.

From a probability to an action

If maintenance fully prevents failure, continuing costs p × C_failure on average and maintaining costs C_maint. So maintain when:

p(failure) > C_maint / C_failure$2,000 / $10,000 = 0.20. With a $20,000 failure the threshold falls to 0.10.

The threshold comes from costs, not from how accurate the model is. The full pipeline: a prior failure rate → a sensor alarm → a Bayesian posterior (Chapter 5) → compare expected costs → act.

Machine learning in one picture

In traditional programming, a person writes rules: IF temperature > 80 THEN alarm. In machine learning, we give the computer examples with answers and it finds the rule, a model ŷ = f(x; θ) with learned parameters θ. ML helps when patterns are noisy, overlapping or curved.

The workflow: collect examples → split into training and test sets → fit the model → evaluate on the unseen test set → deploy. Data leakage happens when test information sneaks into training, so the score looks better than reality.

Measuring a classifier

For a failure detector: a TP (true positive) is a failure caught, an FN is a failure missed, an FP is a false alarm, a TN is a healthy machine correctly passed.

  • Accuracy = (TP + TN) / all. Precision = TP / (TP + FP): how many alarms were real. Recall = TP / (TP + FN): how many failures were caught. F1 = 2 · precision · recall / (precision + recall), a balance of the two.
  • Choose by cost: precision matters when false alarms are expensive; recall matters when misses are dangerous. That is why the lecture prefers model B (92% accuracy, 90% recall) over model A (95% accuracy, 60% recall) for safety.

A brain made of numbers

Qadam: The review is tomorrow, up the mountain road. Gravel, ice, asphalt… which surfaces are safe for my wheels?

Qadam: High grip and low slip feel safe. But where exactly is the line between safe and unsafe?

Aru (on the phone): Don't write the rule yourself. Learn it from examples, one mistake at a time.

A neuron in a computer is a weighted vote. Inputs are multiplied by weights, a bias is added, and the total decides the output. Learning means nudging the weights after each mistake. Stack many neurons in layers and the network can learn curved, complex patterns: faces, spam, medical images.

The perceptron

The perceptron is a single artificial neuron. It was inspired by brain cells, but it is a simplified mathematical model, not a copy of one. For Qadam's surface question it takes two inputs, grip and slip:

z = w₁·x₁ + w₂·x₂ + b · output = 1 (STABLE) if z ≥ 0, else 0 (UNSTABLE)The "step" activation turns the score z into a yes/no decision. The threshold is zero.
  • A weight says how strongly, and in which direction, an input pushes the decision. Grip gets +2 (more grip → safer), slip gets −3 (more slip → less safe).
  • The bias shifts the threshold. A bias of −0.5 means the surface needs some positive evidence before it counts as stable.

Worked example (from the lecture)

  1. Grip 0.8, slip 0.2: z = 2(0.8) − 3(0.2) − 0.5 = 1.6 − 0.6 − 0.5 = +0.5. z ≥ 0, so STABLE.
  2. Slip rises to 0.8: z = 1.6 − 2.4 − 0.5 = −1.3. z < 0, so UNSTABLE.

Learning from a mistake

w_new = w_old + η · (y − ŷ) · xy = true label, ŷ = prediction, η = learning rate (step size). The bias updates the same way with x = 1.

Worked example: one update

  1. Grip 0.8, slip 0.8 is labelled STABLE (y = 1), but the perceptron said UNSTABLE (ŷ = 0). Error = 1 − 0 = +1.
  2. With η = 0.1: grip weight 2 + 0.1 × 1 × 0.8 = 2.08; slip weight −3 + 0.1 × 1 × 0.8 = −2.92; bias −0.5 + 0.1 = −0.4.
  3. All three moved toward predicting STABLE for this point. When a prediction is correct, the error is 0 and nothing changes.

Why one neuron is not enough

A single perceptron can only draw a straight line between the classes. Data that a straight line can split is called linearly separable. The famous counter-example is XOR ("exclusive or"): the classes sit on opposite diagonal corners, so no single line works. Minsky and Papert pointed this out in 1969.

The fix is a neural network: layers of neurons, where the hidden layers between input and output learn intermediate patterns. Each neuron uses a nonlinear activation function, such as the sigmoid from Chapter 7 or ReLU (max(0, z)). Without that nonlinearity, any number of stacked layers still adds up to one straight line.

How a network learns

  1. Forward pass: inputs flow through the layers to a prediction.
  2. Loss: a number measuring how wrong the prediction is.
  3. Backpropagation: send the error backward through the layers to work out how much each weight contributed to it (the chain rule from calculus).
  4. Gradient descent: move every weight a small step downhill on the loss, w_new = w_old − η · ∂L/∂w. This is the same idea as in Chapter 2, now applied to the loss.
  5. Repeat over the whole dataset many times. One full pass is an epoch.

Learning is not memorizing

Data is split three ways: training data to learn the weights, validation data to choose settings and compare models, and test data, never seen during training, to measure the final result. The same example must never appear in both training and test.

ModelTraining accuracyTest accuracyDiagnosis
A98%65%Overfitting: memorized the training data
B91%89%Generalizes: works on new data. Trust this one.

The lecture's analogy: a student who memorizes 18 answers scores 18/18 on those questions and 2/6 on new ones. A warning sign during training is training loss still falling while validation loss rises. Common fixes from the textbooks are more data, a simpler model, regularization and stopping early.

Not all mistakes cost the same. With STABLE as the positive class, calling an icy surface STABLE is a false positive, and it is dangerous; calling dry asphalt UNSTABLE is only a false alarm. And a network is not automatically better: in the lecture's illustration a decision tree scores 82% accuracy (F1 0.79, 1 second to train) while a network scores 88% (F1 0.86, 12 seconds), so the network is more accurate but slower and harder to explain.

Seeing: convolutional networks

A convolutional neural network (CNN) is built for images. Small filters slide across the picture: early layers detect edges and textures, later layers detect shapes, and the final layers decide "cat" or "not cat". The network learns these features from training images instead of a person designing them.

Does recognizing 100 cats mean understanding cats? Not necessarily. Memorizing is remembering the training pictures; learning is recognizing a new cat in a new pose; understanding is knowing what a cat is. Networks learn statistical patterns, and high accuracy alone does not prove understanding.

Myth

Neural networks work the way the human brain works.

Fact

They borrow one idea, weighted connections, and are otherwise simple arithmetic: multiply, add, apply a function, adjust weights to reduce a loss.

Did you know?

Frank Rosenblatt's first perceptron, in 1958, ran on a large IBM computer, and he soon built dedicated hardware, the Mark I Perceptron, with a grid of 400 light sensors as its "eye".

What the law asks for

  • Prohibited AI (the red zone): systems that use subconscious or manipulative methods to distort behaviour, limit informed choice or push people toward harmful decisions.
  • Transparency: users must be told when goods or services are made with AI. Synthetic results must carry a machine-readable mark and a visible or other warning.
  • Data: training data should be lawful, relevant, representative and protected. Check sensitivity, purpose, access, location, retention and vendor terms before sending data to an outside AI service.
  • Copyright: AI-assisted works are protected only where there is a creative human contribution. Creative prompts may be protected too.
  • Audit: AI audits follow information-system audits, plus checks of training-data quality and legality and of prohibited functions.
  • Responsibility: the owner/holder manages risk, documentation and user support; users follow the rules and protect data; vendor contracts cover data use, security, incidents and audit rights. "The model made the decision" is not an accountability strategy.
  • Deployment types: open (parameters available under terms), closed (the owner controls them) or local (inside the owner's infrastructure, without a public network connection). Choose by data sensitivity and risk.

A 7-step compliance playbook

  1. Inventory: find every AI system and use case.
  2. Classify: risk, autonomy and data sensitivity.
  3. Assess: privacy, IP, security, fairness, transparency, sector rules.
  4. Approve: name an accountable owner and the human oversight.
  5. Deploy: with technical and organizational controls.
  6. Monitor: outputs, incidents, drift and complaints.
  7. Review: again whenever the model, data, vendor, purpose or law changes.

Myth

If a human is "in the loop", the system is automatically safe.

Fact

Only if the human really reviews. If a recruiter always accepts the AI's top-ranked CV, the AI is effectively deciding alone.

Did you know?

The English version of the law on the official Adilet legal portal is an unofficial translation. For legal decisions, the official Kazakh or Russian text is the one to rely on.

Key terms

Risk level
How serious the impact of a failure would be: minimal, medium or high.
Autonomy level
Whether a human decides, can override, or cannot intervene.
Synthetic result
Content generated by AI; it must be marked and labelled.
Owner / holder
The organization responsible for an AI system's risk management and documentation.

The end of the road

Qadam left Astana knowing nothing. On the way it searched for routes, improved them, outplayed an opponent, learned from rewards, weighed evidence, tracked itself through noise, chose by expected cost, learned a decision line from examples and, finally, showed it could be trusted. Each step was one idea. Put together, they are what we call artificial intelligence.

Glossary

Every term from the book in one place, with the chapter where it is explained.

A*
Search that expands the lowest f(n) = g(n) + h(n). Optimal with an admissible (tree) or consistent (graph) heuristic. Ch. 1
Activation function
Turns a neuron's weighted sum into its output: step, sigmoid, ReLU. Ch. 8
Actor–critic
RL method where an actor learns the policy and a critic learns values to guide it. Ch. 4
Admissible heuristic
Never overestimates the true remaining cost: 0 ≤ h(n) ≤ h*(n). Ch. 1
Agent
Anything that perceives through sensors and acts through actuators. Ch. 0
Alpha–beta pruning
Skips game-tree branches that cannot change the minimax decision; prune when α ≥ β. Ch. 3
Backpropagation
Sends the error backward through a network to compute each weight's gradient. Ch. 8
Base-rate fallacy
Ignoring how rare a condition is when reading a test result. Ch. 5
Bayes' theorem
P(H | D) = P(D | H)·P(H) / P(D): updating a belief with evidence. Ch. 5
Bayesian network
A directed acyclic graph of random variables, each with a conditional probability table. Ch. 5
Bellman equation
Value of a state = immediate reward + discounted value of the next state. Ch. 4
BFS
Breadth-first search: expands the shallowest plan first, using a FIFO queue. Ch. 1
CNN
Convolutional neural network: learns visual features from edges to objects. Ch. 8
Conditional probability
P(A | B): the probability of A once B is known. Ch. 5
Consistent heuristic
h(n) ≤ cost(n, n′) + h(n′) for every step; needed for A* graph search. Ch. 1
CPT
Conditional probability table: a node's probabilities for each combination of its parents. Ch. 5
Decision threshold
The probability above which acting is cheaper than waiting, e.g. C_maint / C_failure. Ch. 7
Decision tree
A model made of if–then questions; easy to explain, prone to overfitting. Ch. 7
DFS
Depth-first search: expands the deepest plan first, using a LIFO stack. Ch. 1
Discount factor γ
Number between 0 and 1 that sets how much future rewards count. Ch. 4
DQN
Deep Q-Network: a neural network that approximates Q-values. Ch. 4
Emission model
In an HMM, how likely each observation is in each hidden state. Ch. 6
Evaluation function
Estimated score of a game position at the search depth limit. Ch. 3
Expected utility
Probability-weighted average utility of an action's outcomes. Ch. 7
Expectimax
Game search where chance nodes take the expected value instead of the minimum. Ch. 3
Explaining away
Confirming one cause of an effect makes another cause less likely. Ch. 5
Exploration vs exploitation
Trying new actions to learn vs using the best-known action. Ch. 4
F1 score
Harmonic mean of precision and recall. Ch. 7
Filtering
Updating the belief about the current hidden state after each observation. Ch. 6
Frontier
The partial plans waiting to be explored in a search. Ch. 1
Genetic algorithm
Population search with selection, crossover and mutation. Ch. 2
Gradient descent
Step against the slope to minimize a function: x ← x − α·∇f(x). Ch. 2, 8
Heuristic
An estimate of the remaining cost to the goal. Ch. 1
Hidden Markov model
Model of a hidden state that changes over time and is seen only through noisy observations. Ch. 6
Hill climbing
Local search that always moves to a better neighbour and stops at a peak. Ch. 2
Horizon effect
A threat just beyond the search depth stays invisible. Ch. 3
Inference
Computing the probability of hidden variables from observed evidence. Ch. 5
K-Means
Unsupervised clustering: assign points to the nearest centre, move centres to the mean, repeat. Ch. 7
Linear separability
When a straight line (or plane) can split two classes. Ch. 8
Local maximum
A state better than all its neighbours but not the best overall. Ch. 2
Markov property
The next state depends only on the current state (and action). Ch. 4, 6
MDP
Markov decision process: states, actions, transition probabilities, rewards, discount. Ch. 4
Minimax
Game search where MAX takes the maximum and MIN the minimum of child values. Ch. 3
Overfitting
Doing very well on training data but badly on new data. Ch. 7, 8
Perceptron
A single neuron: weighted sum plus bias, then a step decision. Ch. 8
Policy
A rule saying what to do in every state. Ch. 4
Precision
TP / (TP + FP): the share of alarms that were real. Ch. 7
Q-learning
Model-free RL that learns Q(s, a) using the best next action's value (off-policy). Ch. 4
Random forest
Many decision trees trained on random samples, voting together. Ch. 7
Rational agent
Chooses the action with the best expected result given its evidence. Ch. 0, 7
Recall
TP / (TP + FN): the share of real cases that were caught. Ch. 7
Reinforcement learning
Learning a policy from rewards and penalties instead of labelled answers. Ch. 4
Return
The discounted sum of future rewards. Ch. 4
Risk / autonomy level
The two separate axes of Kazakhstan's AI law: impact of failure, and who decides. Ch. 10
SARSA
On-policy TD control: learns from the action actually taken next. Ch. 4
Sigmoid
σ(z) = 1 / (1 + e^(−z)): squeezes any number into 0–1. Ch. 7
Simulated annealing
Local search that sometimes accepts worse moves, less often as the temperature falls. Ch. 2
TD error
δ = r + γV(s′) − V(s): how much better or worse a step went than expected. Ch. 4
Transition model
How a state changes from one step to the next. Ch. 4, 6
UCS
Uniform-cost search: expands the lowest path cost g(n) first. Ch. 1
Value
Expected return from a state (V) or from an action in a state (Q). Ch. 4
Zero-sum game
One player's gain is exactly the other's loss. Ch. 3
